# 디자인 시스템

| 항목 | 내용 |
|---|---|
| 버전 | v1.0 |
| 작성일 | 2026-09-21 |
| 토큰 정의 위치 | `src/app/globals.css` |
| 관련 문서 | `docs/PRD.md` |

> **이 문서의 규칙:** 컴포넌트는 **토큰만 참조**한다. `#fff`, `rgb(...)`, `bg-[#0f7a5a]`, 임의 px 값을 코드에 직접 쓰지 않는다 (PRD 성공 기준 M6).

---

## 1. 원칙

순백 배경의 **미니멀 에디토리얼**. 판단이 갈릴 때는 아래 순서로 결정한다.

1. **여백이 먼저다.** 요소를 더하기 전에 공간을 준다.
2. **위계는 크기로 만든다.** 색이나 박스가 아니라 타이포 스케일로 구분한다.
3. **색은 아끼면 아낄수록 강해진다.** 포인트 컬러는 화면당 1~2회면 충분하다.
4. **모션은 알아채지 못할 때 성공이다.** 존재를 과시하는 순간 실패다.

---

## 2. 컬러

포인트 컬러는 **잉크 그린 하나뿐이다.** 두 번째 색을 추가하고 싶으면 그건 위계 설계가 실패했다는 신호다.

| 토큰 | 값 | Tailwind | 용도 |
|---|---|---|---|
| `--color-bg` | `#FFFFFF` | `bg-bg` | 기본 배경 |
| `--color-surface` | `#F5F5F5` | `bg-surface` | 보조 면, 이미지 플레이스홀더 |
| `--color-ink` | `#111111` | `text-ink` | 본문·제목 |
| `--color-ink-muted` | `#6B6B6B` | `text-ink-muted` | 캡션, 메타 정보, 보조 설명 |
| `--color-line` | `#E5E5E5` | `border-line` | 구분선, 카드 테두리 |
| `--color-accent` | `#0F7A5A` | `text-accent` `bg-accent` | 링크, "진행 중" 배지, 호버, 포커스 링 |
| `--color-accent-hover` | `#0B5C43` | `hover:text-accent-hover` | 포인트 컬러의 호버 상태 |

### 대비비 검증 (WCAG)

| 조합 | 대비비 | 기준 |
|---|---|---|
| `ink` on `bg` | 약 18.9:1 | AAA 충족 |
| `ink-muted` on `bg` | 약 5.6:1 | AA 충족 (본문 사용 가능) |
| `accent` on `bg` | 약 4.9:1 | AA 충족 |
| `bg` on `accent` | 약 4.9:1 | AA 충족 (배지 흰 글씨 가능) |

> `ink-muted`를 `surface` 위에 올리면 대비가 약 5.2:1로 떨어진다. 여전히 AA는 넘지만, 14px 이하 캡션에는 `ink`를 쓴다.

### 금지

- 포인트 컬러를 넓은 면적 배경으로 쓰지 않는다 (배지·버튼 정도까지)
- 색만으로 정보를 구분하지 않는다. "진행 중" 배지는 **색 + 텍스트**를 함께 쓴다 (색각 이상 대응)
- 그림자로 위계를 만들지 않는다. 이 시스템은 선과 여백으로 구분한다

## 3. 타이포그래피

### 3.1 폰트 스택

```css
--font-sans: "Switzer", "Pretendard Variable", Pretendard, system-ui, sans-serif;
```

**Switzer가 한글을 렌더링하지 못하므로 Pretendard가 받는다.** 브라우저는 글리프 단위로 폴백하기 때문에 `"From AI capability to human experience. 기술의 가능성을"` 같은 혼용 문장도 각각 맞는 폰트로 그려진다. 순서를 바꾸면 영문까지 Pretendard로 떨어지므로 **Switzer를 반드시 앞에 둔다.**

검증 결과 (`Switzer-Variable.ttf` cmap 직접 조회): 총 385 코드포인트, 한글 0개. 상세는 `docs/PRD.md` 11장.

로드하는 웨이트는 **400 / 500 / 600 세 종뿐이다.** Switzer는 18종을 제공하지만 이 시스템은 700 이상을 쓰지 않는다 — 큰 사이즈에서는 600이 이미 충분히 무겁고, 요청 수를 줄이는 편이 LCP에 유리하다.

### 3.2 스케일 (6단계 — PRD 상한 준수)

전부 `clamp()` 기반이라 브레이크포인트 없이 뷰포트에 따라 연속적으로 변한다.

| 토큰 | Tailwind | 모바일(375px) | 데스크톱(1280px+) | 웨이트 | 용도 |
|---|---|---|---|---|---|
| `--text-display` | `text-display` | 약 43px | **96px** | 600 | Hero 헤드라인. 페이지당 1회 |
| `--text-h1` | `text-h1` | 약 34px | 56px | 600 | 페이지 제목 |
| `--text-h2` | `text-h2` | 약 26px | 36px | 500 | 섹션 제목 |
| `--text-h3` | `text-h3` | 약 21px | 24px | 500 | 카드 제목, 블록 제목 |
| `--text-body` | `text-body` | 16px | 18px | 400 | 본문 |
| `--text-caption` | `text-caption` | 14px | 14px | 400 | 메타 정보, 태그, 캡션 |

**일곱 번째 단계를 추가하지 않는다.** 필요해 보이면 위계 설계를 다시 본다.

### 3.3 자간·행간

크기가 커질수록 자간을 좁히고 행간을 줄인다. 토큰에 이미 반영돼 있어 별도 지정이 필요 없다.

| 단계 | line-height | letter-spacing |
|---|---|---|
| display | 1.02 | -0.03em |
| h1 | 1.1 | -0.02em |
| h2 | 1.2 | -0.015em |
| h3 | 1.35 | -0.01em |
| body | **1.7** | 0 |
| caption | 1.5 | +0.01em |

> 본문 1.7은 의도적으로 넉넉하다. 한글은 라틴보다 글자당 밀도가 높아 같은 행간이 더 답답하게 읽힌다.

## 4. 레이아웃

### 4.1 컨테이너

```css
.container-page  /* max-width 1280px + 좌우 여백 + 가운데 정렬 */
```

모든 섹션은 이 클래스를 쓴다. 폭을 직접 지정하지 않는다.

### 4.2 좌우 여백 (`--gutter`)

| 뷰포트 | 값 |
|---|---|
| 모바일 (~767px) | **20px** (PRD 명시) |
| 태블릿 (768px~) | 40px |
| 데스크톱 (1280px~) | 64px |

### 4.3 그리드

```css
.grid-page  /* 모바일 4컬럼 → 768px 이상 12컬럼 */
```

12컬럼은 데스크톱에서만 성립한다. 모바일에서 12컬럼을 유지하면 컬럼 폭이 의미를 잃으므로 4컬럼으로 접는다.

### 4.4 세로 간격

| 토큰 | 값 | 용도 |
|---|---|---|
| `--space-section` | 64px → 144px | 섹션과 섹션 사이 |
| `--space-block` | 24px → 48px | 블록·카드 사이, 그리드 gap |

그 외 미세 간격은 Tailwind 기본 스케일(`gap-2`, `mt-4` 등)을 쓴다.

### 4.5 컴포넌트 폭 정책

```tsx
// 올바름 — 부모가 여백을 통제한다
<section className="container-page">
  <ProjectCard className="w-full" />
</section>

// 금지 — 컴포넌트가 자기 폭을 고정한다
<ProjectCard className="w-[320px]" />
```

## 5. 모션

| 토큰 | 값 | 용도 |
|---|---|---|
| `--duration-fast` | 180ms | 호버, 색 전환 |
| `--duration-base` | 320ms | 페이드업, 일반 전환 |
| `--duration-slow` | 600ms | 큰 요소의 진입 |
| `--ease-out-soft` | `cubic-bezier(0.22, 1, 0.36, 1)` | 기본 이징. 빠르게 나갔다 부드럽게 안착 |

### 허용하는 모션 (이게 전부다)

1. **스크롤 페이드업** — `opacity 0→1`, `translateY 16px→0`, `--duration-base`. 요소당 **1회만** 실행한다
2. **카드 호버** — 이미지 `scale(1.3)`, `--duration-base`. 확대폭이 크므로 시간도 길게 잡는다
3. **링크·버튼 호버** — 색 전환, `--duration-fast`

### 금지

- 패럴랙스 (PRD 명시)
- 스크롤에 물리는 지속적 애니메이션
- 페이지 진입 시 순차 등장 연출(스태거)이 0.5초를 넘는 것
- 자동 재생 캐러셀

### 접근성

`prefers-reduced-motion: reduce`를 `globals.css`에서 전역 차단한다. Framer Motion으로 개별 구현할 때도 이 설정을 존중해야 한다.

## 6. 폰트 조달 — 결정 근거

두 폰트 모두 **CDN에서 받고, 저장소에는 폰트 파일을 넣지 않는다.**

| 폰트 | 출처 | 라이선스 | 자체 호스팅 |
|---|---|---|---|
| Switzer | `api.fontshare.com` (Indian Type Foundry) | Fontshare Free Font EULA | **불가** |
| Pretendard | `cdn.jsdelivr.net` (동적 서브셋) | SIL Open Font License 1.1 | 가능하나 미채택 |

### Switzer를 자체 호스팅하지 않는 이유

Fontshare EULA 02조는 폰트 파일을 **public server에 업로드하는 것을 금지**한다. 웹사이트에서 사용하는 것 자체는 01조로 명시 허용되지만, GitHub **public 저장소**에 `.woff2`를 커밋하면 누구나 원본 파일을 내려받을 수 있어 "사용"이 아니라 "배포"로 읽힐 소지가 있다. 이 프로젝트의 저장소는 public이므로(PRD 10.2) 해당한다.

같은 EULA 서문이 대안을 제시한다 — Fontshare API를 통해 **파운드리 서버에서 직접 방문자에게 전달**하는 방식이며, 라이선시가 폰트를 다운로드하지 않는다. 이 경로를 쓴다.

### Pretendard를 동적 서브셋으로 받는 이유

한글 폰트는 글자 수 때문에 라틴 폰트보다 10배 이상 무겁다. 동적 서브셋은 유니코드 범위별로 파일을 쪼개두고 **화면에 실제로 쓰인 글자 범위만** 내려받으므로, 1.3MB 단일 파일 대신 수십 KB만 전송된다 (성공 기준 S3: LCP 2.5초).

### 감수하는 위험

외부 CDN 두 곳에 의존한다. 장애 시 폰트는 시스템 폰트로 폴백되고 레이아웃은 유지된다(`font-display: swap`). 콘텐츠가 확정되는 5단계에서 직접 서브셋을 만들어 자체 호스팅하는 방안을 재검토한다 — **단, Pretendard만 해당한다.** Switzer는 라이선스상 불가하다.

## 7. 다국어 표기

`LocalizedText = { ko: string; en: string }`. 상세는 `docs/PRD.md` 6·9장.

| 항목 | 규칙 |
|---|---|
| 기본 언어 | 한국어 |
| Hero 헤드라인 | 두 언어 모드 공통으로 **영문 유지** |
| 고유명사 | 도구 이름(`Figma`, `Claude Code`), URL, 이메일은 번역하지 않음 |
| 토글 위치 | 글로벌 헤더 우측, `KOR / EN` |
| 숫자·기간 | 언어 무관 동일 표기 (`2026.03 - 2026.06`) |

### 타이포 주의

영문은 같은 폰트 크기에서 한글보다 짧게 끝난다. **영문 모드에서 줄바꿈이 어색해지는 지점**을 4단계에서 반드시 확인한다 — 특히 Hero와 카드 제목.

## 8. 체크리스트

컴포넌트를 만들 때마다 확인한다.

- [ ] 하드코딩된 색·크기 값이 없는가 (토큰만 참조)
- [ ] 타이포가 6단계 안에서 해결되는가
- [ ] 폭을 컴포넌트가 아니라 부모가 통제하는가 (`w-full`)
- [ ] 375px에서 가로 스크롤이 없는가
- [ ] 키보드 Tab으로 도달 가능하고 포커스 링이 보이는가
- [ ] 텍스트가 전부 `LocalizedText`인가 (ko/en 양쪽 존재)
- [ ] 한글·영문 혼용 문장에서 폰트가 의도대로 갈리는가
- [ ] 모션이 허용 목록(5장) 안에 있는가

## 1. 목적

채용 지원서에 첨부할 개인 포트폴리오 웹사이트를 만든다.

이 사이트의 핵심 명제는 **"AI로 디자인을 직접 구현할 줄 아는 디자이너(AX 디자이너)"** 이며,
사이트 자체가 그 명제의 증거물이다. 즉 **실린 내용(작업물)과 그릇(이 사이트)이 같은 주장을 해야 한다.**

세 가지를 동시에 증명한다.

1. **디자인 감각** — 절제된 에디토리얼 레이아웃, 타이포 위계, 여백 운용
2. **구현 능력** — Next.js로 직접 만들고 GitHub/Vercel로 직접 배포한 실제 URL
3. **AI 워크플로 역량** — 여러 AI 엔진을 목적에 따라 갈아 쓰는 방식, 프롬프트 설계 관점

### 이 사이트가 하지 않는 것
- 모든 작업물의 아카이브가 아니다. **선별된 대표작만** 싣는다.
- 기술 블로그가 아니다. Notes는 워크플로 인사이트에 한정한다.

## 6. 콘텐츠 모델

콘텐츠는 **한 곳**에서 관리한다. 프로젝트를 추가할 때 컴포넌트 코드를 고치지 않는 것이 성공 기준 S6이다.

### 6.1 다국어 문자열 타입

**모든 사용자 노출 문자열은 예외 없이 아래 타입을 쓴다.** 한쪽 언어를 빠뜨리면 타입 에러가 나므로, 번역 누락이 런타임이 아니라 빌드에서 잡힌다 (성공 기준 M9).

```ts
type LocalizedText = { ko: string; en: string };
type Locale = "ko" | "en";
```

예외: 고유명사(도구 이름 `Figma`, `Claude Code` 등), URL, 이메일은 단일 문자열로 둔다.

### 6.2 프로젝트 스키마

```
slug       string                 URL 경로 (언어 무관, 고정)
title      LocalizedText          제목
summary    LocalizedText          한 줄 요약
category   "ui-ai" | "branding"   카테고리
status     "done" | "wip"         완성 / 진행 중
role       LocalizedText          역할
period     string                 기간 (예: 2026.03 - 2026.06)
tools      string[]               사용 도구 (고유명사, 번역 없음)
thumbnail  string                 public/projects/[slug]/ 기준 경로
video      string?                카드·상세 영상 (선택)
links      { label: LocalizedText; url: string }[]   실제 서비스 링크 등 (선택)
body       {
             problem:     LocalizedText
             process:     LocalizedText
             aiWorkflow?: LocalizedText   브랜딩 프로젝트는 생략 가능
             result:      LocalizedText
             learnings:   LocalizedText
           }
```

### 6.3 초기 프로젝트 5건 (내용은 플레이스홀더, 구조만 완성)

| slug | 제목 | 카테고리 | 상태 | 비고 |
|---|---|---|---|---|
| `todo-tool` | 업무 생산성 To-do 툴 | UI·AI 구현 | 완성 | 사용자 데이터 서버 구축, 앱 배포, Codex 사용. 실제 링크 미정 |
| `google-maps` | Google Maps 개선 | UI·AI 구현 | 완성 | 인터랙티브 애니메이션 → 영상 인코딩. **카드에 영상 사용** |
| `co-us` | CO-US | UI·AI 구현 | 진행 중 | 과정 중심으로 서술 |
| (미정) | 3학년 과제 | 미정 | 완성 | 내용 추후. 임시 slug 제안: `year3-project` |
| `grad-exhibition` | 졸업전시 브랜딩 | 브랜딩·그래픽 | 미정 | 로고·타이포·포스터·굿즈·도록 |

### 6.4 에셋 규칙

## 7. 디자인 방향 (요약 — 상세는 2단계 `docs/DESIGN_SYSTEM.md`)

- **레퍼런스:** Framer 템플릿 "Kiban" — **분위기와 구조만** 참고. 코드·이미지·문구 복사 금지, 레이아웃은 새로 설계
- **톤:** 순백 배경의 미니멀 에디토리얼. 넓은 여백, 강한 타이포 위계
- **컬러:** 배경 `#FFFFFF` / 보조 면 `#F5F5F5` / 본문 `#111111` / 보조 텍스트 `#6B6B6B` / 구분선 `#E5E5E5`
- **포인트 컬러 (확정):** **잉크 그린 `#0F7A5A`** — 1개만 사용. 링크, "진행 중" 배지, 호버에 한정
  - 흰 배경 대비 약 4.9:1 → WCAG AA 충족
  - 블루 계열보다 덜 흔해 개성이 생기고, 흑백 에디토리얼 톤을 해치지 않음

### 이 방식의 알려진 한계 (수용함)

사용자가 구현 난이도와 마감(D-8)을 고려해 선택한 방식이며, 아래 세 가지를 감수한다.

1. **영문 페이지를 링크로 공유할 수 없다.** 공유된 URL은 항상 한국어 기본으로 열린다.
2. **검색엔진은 한국어 콘텐츠만 인식한다.** 영문 검색 유입은 기대할 수 없다.
3. 영문 텍스트가 초기 HTML에 포함되므로 **번들에 두 언어가 모두 실린다.** 텍스트라 용량 영향은 미미하다.

> 나중에 URL 분리(`/en`) 방식으로 바꾸고 싶어지면, 콘텐츠가 이미 `{ ko, en }` 구조라서 **데이터는 그대로 두고 라우팅만 추가**하면 된다. 이번 선택이 막다른 길은 아니다.

## 11. 폰트 — 확정 및 주의사항

### 11.1 확정 내용

| 용도 | 폰트 | 조달 | 라이선스 |
|---|---|---|---|
| **라틴 문자·숫자** | **Switzer** | `api.fontshare.com` (파운드리 API) | Fontshare Free Font EULA |
| **한글** | **Pretendard** | `cdn.jsdelivr.net` 동적 서브셋 | SIL OFL 1.1 |

**폰트 파일은 저장소에 넣지 않는다.** Fontshare EULA 02조가 폰트 파일의 public server 업로드를 금지하며, 이 저장소는 public이다. 같은 EULA 서문이 제시하는 파운드리 API 경로를 쓴다. 결정 근거 상세는 `docs/DESIGN_SYSTEM.md` 6장.

로드 웨이트는 **400 / 500 / 600 세 종**으로 제한한다 (보유 18종 중).

### 11.2 Switzer는 한글을 렌더링할 수 없다 — 검증 결과

`Switzer-Variable.ttf`의 cmap 테이블을 직접 조회한 결과다.

| 문자 | 코드포인트 | 포함 여부 |
|---|---|---|
| `A` | `0x0041` | 있음 |
| `—` (em dash) | `0x2014` | 있음 |
| `가` | `0xAC00` | **없음** |
| `맹` | `0xB9F9` | **없음** |
| `힣` | `0xD7A3` | **없음** |
| `ㄱ` (자모) | `0x3131` | **없음** |

총 코드포인트 **385개** — 라틴 전용 서체다.

### 11.3 대응 방식

`font-family`를 Switzer → Pretendard 순으로 지정한다. 브라우저가 글리프 단위로 폴백하므로, 한 문장 안에 한글과 영문이 섞여도 각각 맞는 폰트로 렌더링된다.

```css
--font-sans: "Switzer", "Pretendard", system-ui, sans-serif;
```

- `font-display: swap`으로 FOUT 최소화, `preconnect`로 CDN 연결 지연 단축
- 외부 CDN 두 곳에 의존한다. 장애 시 시스템 폰트로 폴백되고 레이아웃은 유지된다
- **성공 기준 M10**: 한글이 폴백되지 않고 깨지는 지점이 0건이어야 한다
